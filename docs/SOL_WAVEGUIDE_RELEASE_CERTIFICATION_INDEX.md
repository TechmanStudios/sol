# SOL Waveguide Release Certification Index / RC Audit Registry

## 1. Purpose

The `SOL Waveguide Release Certification Index` (also referred to as the `RC Audit Registry`) represents a canonical, deterministic historic index of verified release candidate audits. 

By collecting independent audit reports generated by the `Release Certification Validator`, the Release Certification Index compiles them into a single, cohesive timeline and registry catalog, allowing verification of which Release Candidates (RCs) are audit-verified and what audit trails prove their integrity.

This step establishes the following governance chain:
```text
Release Certification Validator / Independent Audit Verifier
→ Release Certification Index / RC Audit Registry (This Module)
→ future Certified Release Publication Manifest
```

---

## 2. Architecture & Design

Like the rest of the SOL Waveguide verification layer, the Release Certification Index runs purely as a side-effect-free audit indexing layer:
* **No State Mutation**: It never modifies the codebase or the active deployment state.
* **No Live Runtime Execution**: It does not schedule or execute real compiler/optimizer passes or run production pipelines.
* **Deterministic Hashing**: All hashes are generated using standard `sha256` hashing on sorted JSON keys (canonical serialization).
* **Self-Referential Exclusions**:
  * For entries: `registry_entry_digest` is excluded from the input when computing its own hash.
  * For the registry: `audit_registry_digest` is excluded from the input when computing its own hash.

## 4. Reason Codes

The Release Certification Index emits structured reason codes during validation to provide clean audit trails:
* `RELEASE_CERT_INDEX_ENTRY_CANONICAL`: The entry format matches structural specifications.
* `RELEASE_CERT_INDEX_SOURCE_AUDIT_REPORT_VALID`: The source audit report parses and validates.
* `RELEASE_CERT_INDEX_AUDIT_REGISTERED`: The audit status was verified and index entry registered.
* `RELEASE_CERT_INDEX_COUNTS_VALID`: Top-level registry counts match entry counts exactly.
* `RELEASE_CERT_INDEX_TIMELINE_CANONICAL`: The timeline list is ordered alphabetically by `rc_id` without gaps.
* `RELEASE_CERT_INDEX_VALID`: The overall index verified successfully with no errors or mismatches.

---

## 5. Timeline Generation Rules

The timeline captures audit state changes in a strictly deterministic sequence:
1. **No Timestamps**: Wall-clock timestamps are omitted to ensure total parity across repeat runs.
2. **Deterministic Ordering**: Timeline entries are sorted alphabetically/lexically by `rc_id` (so `SOL-WAVEGUIDE-RC1` always precedes `SOL-WAVEGUIDE-RC2`).

---

## 6. Verification & Parity

To verify the release certification index, run:
```bash
pytest tests/test_waveguide_release_certification_index.py
```
This suite verifies deterministic digest calculations, timeline ordering, correct count aggregation, schema compliance, and exception handling for missing or malformed inputs.

---

## 7. Limitations & Caveats

* **Shadow/Sandbox Verification Only**: All verification is performed against static configuration data and record traces. It does not validate physical hardware execution or live deployments.
* **No Real-Time Signing**: Cryptographic signing is simulated through SHA256 digest validation of the promotion court verdicts and manifest registers.
